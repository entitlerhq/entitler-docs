# Contributing to the Entitler docs

This repository holds the pages of [docs.entitler.dev](https://docs.entitler.dev): MDX files, their
navigation files and the checks that run on every pull request. The site that renders them, the API
reference and the search are built elsewhere from this content.

## Layout

```
content/docs/
  meta.json             Navigation for the top level: the order of its pages and folders.
  index.mdx             The home page, at /.
  guides/
    meta.json           The folder's title and the order of its pages.
    first-page.mdx      A page, at /guides/first-page.
```

A file's path is its address: `content/docs/guides/first-page.mdx` is `/guides/first-page`,
and an `index.mdx` is its folder's address.

## Pages

Every page starts with frontmatter holding a `title` and a one-sentence `description`, both in
sentence case, and nothing else:

```mdx
---
title: Server keys
description: Keep a server key on your servers, and give browsers and apps their own credentials.
---
```

The title is the page's heading, so the body starts with text or a `##` heading, never a `#` one.

Write Markdown with GitHub's extensions (tables, task lists, strikethrough). Pages hold no imports,
exports or `{expressions}`, and no HTML or JSX elements beyond the components below.

## Navigation files

Each folder's `meta.json` lists its pages and folders in order, by file or folder name without
`.mdx`, and may give the folder a `title`:

```json
{
  "title": "Guides",
  "pages": ["first-page", "second-page"]
}
```

An entry can also be a link, `"[API reference](/api-reference)"`, or a separator, `"---Learn---"`.
Every folder with pages needs a `meta.json`, and every page must be listed in it. Link entries are
checked like links in pages. The API reference is generated by the site from Entitler's OpenAPI
documents, so it is a link entry here, never a page.

## Components

Pages may use these components and no others. Each takes only the props listed, as quoted strings,
never `{expressions}`: the site refuses to build a page that breaks these rules.

| Component | Props | Use |
| --------- | ----- | --- |
| `<Callout>` | `type`: `note` (default), `tip` or `warning`; `title`: optional text, `Note`, `Tip` or `Warning` by default | A note or warning set apart from the text. |
| `<Tabs>` | none; its tabs are named by their `<Tab>`s | Alternatives the reader picks between, such as one example in several languages. Holds two or more `<Tab>`s. |
| `<Tab>` | `value`: the name shown on its tab | One tab's content. |
| `<Cards>` | none | A grid of `<Card>`s. |
| `<Card>` | `title`: text; `href`: an internal or external link | A link to another page, with a sentence about it as its content. |

````mdx
<Callout type="warning">
  Keep server keys out of browsers and mobile apps.
</Callout>

<Tabs>
  <Tab value="curl">

```bash
curl https://api.entitler.dev/keys/self -H "Authorization: Bearer $ENTITLER_KEY"
```

  </Tab>
  <Tab value="JavaScript">

```javascript
await fetch('https://api.entitler.dev/keys/self', { headers: { Authorization: `Bearer ${key}` } })
```

  </Tab>
</Tabs>
````

Leave a blank line around Markdown inside a component, as above, so it is read as Markdown.

## Code

Label every code block with its language, one of `bash`, `javascript`, `typescript`, `json`,
`kotlin` or `swift`, so the site highlights it: ```` ```bash ````. Use `bash` for curl and other
shell commands.

## Links

- Link to another page by its address from the root: `[First page](/guides/first-page)`, with an
  anchor when needed: `[A heading](/guides/first-page#a-heading)`. An anchor is the heading in lower case,
  with spaces as hyphens and punctuation left out.
- Link to the API reference as `/api-reference` only; its route pages are generated.
- Link to other sites with full `https://` addresses.

## Copy

- Australian English (`organisation`, `colour`, `licence` as a noun), sentence case for titles and
  headings, and no emoji.
- Never write "get" ("get started", "what a customer gets", "the answer your app gets"): name the
  thing instead, such as "Quick start", "the customer's entitlements" or "the answer your app
  receives". Questions ("What happens when…?") are fine.
- No vague "what" clauses, such as "what they can use" or "what each plan includes": name the
  thing, such as "their features and limits".
- Every fact must match the live API, described by the OpenAPI documents at
  `https://api.entitler.dev/customers/openapi.json` and `https://api.entitler.dev/keys/openapi.json`.
  Show requests with curl against `https://api.entitler.dev`, with keys from `$ENTITLER_KEY`.
- Describe the product and the API only: no internal names, plans or dates for future features.

## Checks

Install [Bun](https://bun.sh) 1.3 or later and [Vale](https://vale.sh) 3, then from the repository
root:

```sh
bun install
bun run check:pages   # every page compiles with stand-in components; frontmatter and navigation are valid
bun run check:links   # internal links and anchors resolve
bun run check:prose   # Vale: Australian English spelling, sentence-case headings, the "get" rule
bun run check         # all three
```

Words the dictionary lacks, such as product names, go in
`styles/config/vocabularies/Entitler/accept.txt`, one per line (regular expressions allowed).

Every pull request runs these checks, and one required check, **All checks passed**, succeeds only
when every one of them does. Pull requests are merged with the rebase method. A merge to `main`
rebuilds docs.entitler.dev within a few minutes.
